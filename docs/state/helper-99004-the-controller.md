# the_controller Helper

## StateDef 99004000: 個別挙動ルーティング

### 共通ID後の個別挙動分岐

`99004`は、ライフ管理と複数の演出挙動を担当する常駐Helperである。`99000`の共通IDルーターから`99004`へ振り分けられた後、`99004`自身は処理本体を直接まとめず、挙動ごとの個別ルーターへ振り分ける。

Rootが前方ダッシュStateDef `110`または後方ダッシュStateDef `111`の場合は、ライフ管理へ移る前にPlayerPush無効化フラグ`var(13)`を`1`にする。それ以外では毎tick`0`へ戻す。

最初の個別挙動はライフ管理である。`99004`からライフ管理StateDefへ遷移し、ライフ管理の完了後に次の個別挙動ルーターへ進む。

```text
StateDef -2
  → 共通IDルーター
  → StateDef 99004000: the_controller監視
  → StateDef 99004001: 個別挙動（ライフ管理）
  → StateDef 99004002: オーラバウンドルーター
  → StateDef 99004011: 4001バウンド個別
  → StateDef 99004012: 4002バウンド個別
  → StateDef 99004013: 4003バウンド個別
  → StateDef 99004999: 最終処理
  → StateDef 5150
```

個別挙動の順序は、ライフ管理を初回とする。以降は個別挙動ルーターが次の挙動を選択し、処理完了後は最終処理を経由して`5150`へ移動する。

`99004002`はRootのStateNoを監視し、`4001`、`4002`、`4003`に対応してそれぞれ`99004011`、`99004012`、`99004013`へ振り分ける。各バウンド個別StateDefは設定を適用した後、`99004999`へ移動する。

個別挙動の追加や遷移責務に関する実装指針は、[ADR 015: the_controller 99004の個別挙動ルーター](../ADR/015-the-controller-99004-routing.md)を参照する。

### StateDef 99004001: ライフ管理

Action `99004`の当たり判定をRootの位置へ追従させ、PlayerPush無効化フラグ`var(13)`が`0`の場合はPlayerPushで相手を押し返す。フラグが`1`の場合はPlayerPushを無効にする。`HitOverride`によって相手の攻撃を受け、命中時は`GetHitVar(damage)`を`var(11)`へ保存し、`var(12)`へ設定して無敵期間を開始する。本体は次のフレームに`var(11)`を読み取り、ライフへ反映する。

### StateDef 99004002: オーラバウンドルーター

ライフ管理の完了後に入り、RootのStateNoと`private-time`を監視して、`99004011`、`99004012`、`99004013`へ振り分ける。個別処理がないフレームも`99004999`へ進み、次フレームの`-2`ルーティングへ戻す。

### StateDef 99004011: 4001バウンド個別

RootのStateNo `4001`に対応するバウンド定義を適用し、`99004999`へ移動する。

### StateDef 99004012: 4002バウンド個別

RootのStateNo `4002`に対応するバウンド定義を適用し、`99004999`へ移動する。

### StateDef 99004013: 4003バウンド個別

RootのStateNo `4003`に対応するバウンド定義を適用し、`99004999`へ移動する。

### StateDef 99004999: 最終処理

個別挙動の処理を終了し、`SelfState value=5150`で常駐Helperの情報を隠す。次フレームはStateDef `-2`から共通IDルーティングへ戻る。
