# エフェクト作業規則

## 対象

この規則は、暗転、発光、色変化、フラッシュなどの画面効果、および複数の技から利用する視覚エフェクトの追加・変更に適用する。

エフェクト文書群の入口と登録状況は[エフェクト設計](design/008-effects.md)、各エフェクトの表現設計と現在の設定値は`docs/design/effect/`の個別文書で管理する。CNS上のStateDef、Controller、Trigger、変数、Helper、Explodなどの実装内容は`docs/state/`の対応文書で管理する。

共通エフェクトの1000番予約、用途別出現StateDef、変数による全設定値の保持、および末尾`900`〜`999`の共通実行領域は[共通エフェクト設計・実装規約](design/effect/AGENTS.md)に従う。

非常駐Helperの責務bitmap、共通経過tick、固定順ルーティングおよび共通終端は[非常駐Helper共通実行基盤](design/014-transient-helper-runtime.md)と[ADR 034](ADR/034-transient-helper-responsibility-routing.md)に従う。

## 設計を実装より先に登録する

新しいエフェクト種別または既存エフェクトの新しい表現パターンを追加する場合は、CNSへStateDefやルーティングを実装する前に、`docs/design/008-effects.md`へエフェクトを登録し、`docs/design/effect/`へ個別設計文書を作成または更新する。

登録時は、ユーザーが確定した範囲で次を記載する。

- エフェクト番号または識別方法
- 名称
- 表現目的と見た目
- 適用対象
- 使用する技または場面
- 発動条件と終了条件
- 継続時間
- 色、明度、透過、合成などの変化
- 他のエフェクトと同時に成立した場合の優先順位または置換方針

未確定の見た目や数値を推測で補わない。CNSへ実装する前はユーザーが確定した要求を記載する。実機調整中に変更した値はCNS上に留め、設計文書へ重複記載しない。ユーザーが検収した後に確定値を設計文書へ反映する。

## 番号と実装先を確認する

エフェクト番号を新規割当する場合は、`docs/design/008-effects.md`、`docs/design/effect/`の個別文書、対象CNS、`docs/state/`の実装文書、変数一覧を検索し、同じ分類の既存番号との衝突がないことを確認する。文書番号とCNSで使用するエフェクト番号を同一の番号空間として扱わない。

AIRのAction番号を割り当てる場合は、現行AIRでの使用状況に加え、登録済みSpriteの構成と、そのSpriteへ今後割り当てるAction番号を確認する。Action番号とSpriteのGroup・Image番号は別の番号空間であり、AIRには参照するSpriteを明示する。Action番号が現時点で未使用という理由だけで採番せず、別のSpriteに割り当て得る番号を避ける。同じSpriteの表示違いに別Actionを設ける場合も、この確認を行う。

画面全体へ適用する`AllPalFX`暗転、発光、色変更は現在実装されていない。新規導入時はRootの技StateDefへ色指定や時間管理を直接追加せず、実行主体、要求保持および複数要求の優先順位を先に設計してADRへ記録する。廃止済みの旧実装と判断理由は[ADR 021: AllPalFX暗転のController管理](ADR/021-controller-allpalfx-routing.md)を参照する。

## 実装後の文書同期

CNS実装の調整中は、試験値を`docs/state/`へ同期しない。ユーザーが挙動を検収した後、検収済みの動作を理解するために必要なStateDef、Controller、Trigger、変数、発動条件、継続時間、色指定、遷移先を記録する。

WinMUGEN実機で試験中の値はCNS上だけで管理する。ユーザーが見た目を検収するまでは、試験値を設計文書またはステート文書へ転記しない。検収後、確定した値を必要な文書へ反映する。

試験中のCNS実装と設計文書またはステート文書の差異は自動同期しない。検収済み仕様との差異を検出した場合は、CNSまたは文書を自動変更せず、差異を報告して指示を待つ。

## 事前登録を必要としない変更

次の変更はエフェクトの表現設計を変更しない限り、`docs/design/008-effects.md`への事前登録および個別設計文書の新規作成を必要としない。

- 同じエフェクトを別の技から呼び出す
- 見た目を変えないStateDef分割またはルーティング整理
- Trigger、遷移、残り時間更新の不具合修正
- 既存の確定済み設定へ実装を一致させる修正

ただし、使用する技や発動条件など、エフェクト一覧に記載している情報が変わる場合は、実装と同時に該当記述を更新する。
