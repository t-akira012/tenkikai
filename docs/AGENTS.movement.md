# 移動・速度管理規約

## 対象

通常移動、浮遊移動、ダッシュ、回避、突進、ワープの予備・終了動作、技固有の継続移動へ適用する。

## 継続移動要求

時間経過に沿った継続移動は、個別StateDefからRoot変数へ期限付き要求を発行し、StateDef `-3`の共通処理で速度へ反映する。

個別StateDefは対象軸の有効期限、目標速度、加減速度を毎tick更新する。共通処理は要求元のStateDef番号を判定してはならない。新しい移動StateDefを追加する場合も、共通処理へStateNo分岐や除外条件を追加せず、同じ要求契約を使用する。

水平と垂直の要求は独立して管理する。一方の軸だけを使用する移動は、他方の軸の要求を変更しない。変数の割当は[Root変数一覧](state/var-list-root.md)を正本とする。

有効期限は`private-gametime`を基準とする。個別StateDefとStateDef `-3`の実行順を吸収できる短いリースを使用し、要求元が更新を停止すると自動的に期限切れになるようにする。単純なON/OFFフラグを毎tick初期化する方式へ置き換えてはならない。

要求が有効な間は、通常は現在速度を目標速度へ近づける。最低速度保証モードでは、現在速度が要求方向の目標速度へ達していない場合だけ加速し、既に目標速度を上回っている同方向の慣性を減速してはならない。方向反転では0を通過してから反対方向へ加速する。

水平要求が期限切れになった後は、期限切れ時のX速度を起点とする半コサイン曲線で速度を0へ減衰させる。開始時の`abs(Vel X)`が`3`以下なら32tick、`3`を超える場合は16tickとし、減速中に時間区分を再判定しない。新しい水平要求、水平排他要求、被弾または完全停止が成立した場合は、進行中の曲線を解除する。垂直要求の期限切れ後は、最後の加減速度を使ってY速度を0へ近づける。

## 個別速度処理

一度だけの反動、推進、ノックバックには、対象StateDefの個別`VelAdd`を使用してよい。瞬間ワープによる位置変更時の完全停止には個別`VelSet`を使用し、速度と両軸の継続移動要求を解除する。ワープの予備動作へ入るだけで速度を0へ戻してはならない。

被弾速度はM.U.G.E.Nの被弾処理へ委ねる。被弾中は継続移動要求を無効化するが、共通移動処理で被弾速度を上書きしない。

技固有の特殊軌道が共通移動と競合する場合は、対象軸の期限付き排他要求を発行する。共通処理は排他期限だけを判定し、技のStateDef番号を判定しない。特殊軌道側は、共通要求と合成するか、対象軸を排他的に置き換えるかを明示する。

## 位置操作

途中経路を表示しない瞬間ワープ、出現位置選択、画面端補正、接地補正には`PosAdd`または`PosSet`を使用する。時間経過に沿った通常移動を`PosAdd`で実装しない。

## 文書と検証

移動方式を変更した場合は、対象の設計文書、ステート文書、Root変数一覧を同期する。目標速度、加減速度、要求期限、解除条件、位置補正を確認し、`make check`を実行する。実機では開始、入力解除、方向反転、StateDef遷移、被弾、画面端、接地、ワープ前後を確認する。
