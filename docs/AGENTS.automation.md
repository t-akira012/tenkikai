# オートメーション規約

## 用語

WinMUGENのキャラクター自動操作モードを、このリポジトリでは「オートメーション」と表現する。

## `command`とオートメーション

WinMUGENの`command`は、プレイヤーが操作している場合にのみ入力される。オートメーション中は`command`が入力されないため、技遷移、移動、速度の増減など、プレイヤー操作とオートメーションの両方で成立させる処理が`command`を直接Triggerに使用してはならない。

プレイヤー操作とオートメーションは、どちらも通常変数のビットフラグへ入力結果を反映する。技遷移や移動処理は入力元を判定せず、共通のビットフラグをTriggerとして使用する。

```text
プレイヤー操作のcommand → StateDef -1でビットへ変換 ┐
                                                        ├→ 入力・技フラグ → 技遷移・移動処理
オートメーションの判断 → 同じビットへ反映            ┘
```

## `command`を使用できる場所

`command`をTriggerに使用できるのは、StateDef `-1`に置く、プレイヤー入力をビットフラグへ変換するState Controllerだけとする。

StateDef `-1`の`ChangeState`、移動、速度の増減、その他の実処理は、`command`ではなく変換後のビットフラグをTriggerにする。StateDef `-1`以外では、StateDef `-2`、StateDef `-3`、通常StateDef、Helper用StateDefを含め、`command`をTriggerへ一切記述してはならない。

`triggerall`にも`command`を記述してはならない。入力をビットへ変換するState Controllerでは、個別の`trigger1`、`trigger2`などで`command`を評価する。

## StateDef `-1`の記述順序

State Controllerは記述順に実行される。同一フレームの入力を後続処理へ反映するため、StateDef `-1`では、`command`入力をビットへ変換するState Controller群を、ビットを参照する`ChangeState`群より前に記述する。

StateDef `-1`は、次の順序で構成する。

1. 入力フラグの初期化または更新
2. プレイヤー操作の`command`入力をビットへ変換する処理群
3. StateDef `-1`で行う場合は、オートメーションによる入力・技フラグを確定する処理群
4. 入力・技フラグを参照する`ChangeState`、移動量または速度の増減などの処理群

オートメーションの判断をStateDef `-1`以外で行う構成でも、StateDef `-1`内ではビット変換処理群を`ChangeState`群より前に置く。後続処理が参照する時点までに、プレイヤー操作とオートメーションのどちらを入力元とするかを確定させる。

入力・技フラグを参照する処理群の内部では、`ChangeState`、移動量、速度などのController順序をそれぞれの挙動と実行条件に基づいて決める。ビット変換処理を前置するために、既存の実処理Controllerを無条件に並べ替えてはならない。

## 入力フラグの更新

入力フラグには、左、下、上、右などの方向入力と、各技を発動するための入力を割り当てる。

プレイヤー操作では、`command`が真の場合に対応ビットを立て、偽の場合に対応ビットを下ろす。オートメーションでも、判断結果の真偽を同じビットへ反映する。一度立てたビットを無条件に保持せず、現在の入力状態、1tickだけの発動要求、または複数tick保持する要求のどれであるかを定義し、その有効期間に従って明示的に解除する。

同じビットに対してプレイヤー操作とオートメーションが同時に異なる値を書き込まないよう、現在の操作モードに応じて入力元を選択する。複数のState Controllerが同じ通常変数を更新する場合は、各Controllerが担当外のビットを維持し、後続Controllerが先行Controllerの結果を消去しないようにする。

## 通常変数のビットフラグ

利用可能な通常変数は`var(0)`から`var(59)`までの60個である。通常変数は32ビット符号付き整数であり、利用可能な値の範囲は`-2147483648`から`2147483647`までである。

入力または技ごとに通常変数を1個ずつ消費してはならない。1個の通常変数へ複数の入力・技フラグを割り当て、ビット演算で個別に読み書きする。

- ビットが立っているかの判定：`(var(N)&MASK)!=0`
- ビットを立てる値：`var(N)|MASK`
- ビットを下ろす値：`var(N)&~MASK`

ビットは0から31まで使用できる。ビット31は符号ビットであり、単独のマスク値は`-2147483648`となる。このビットが立つと変数全体の値は負数になり得るため、変数全体の正負や特定の合計値でフラグを判定せず、必ず対象マスクとのビット演算で判定する。

ビットを立てたり下ろしたりする場合は、同じ通常変数に格納された他のビットを維持する。入力ビットマップで定めた毎tickの初期化を除き、複数フラグを格納した通常変数へ`0`または単一のマスク値をそのまま代入し、担当外のフラグを消去してはならない。

## Var割り当ての管理

入力フラグ用のVar番号と、各入力・技に対応するビット位置は、[入力ビットマップ](AGENTS.input-map.md)を正規定義として管理する。ユーザーの明示的な承認なしにVar番号、ビット位置、マスク値、入力の意味を変更してはならない。

新しいフラグを追加する前に、入力ビットマップ、[変数一覧](state/var-list.md)、CNS内の代入・参照を確認し、既存用途のあるVarまたはビットを再利用してはならない。

入力フラグの追加または割り当て変更を行った場合は、CNSと同時に変数一覧へ次の内容を反映する。

- 使用するVar番号
- ビット位置とマスク値
- 対応する方向入力または技
- フラグを書き込むStateDef
- フラグを参照するStateDef
- フラグを解除する条件と有効期間

## 実装確認

コマンド入力またはオートメーションに関する変更後は、次を確認する。

- StateDef `-1`のビット変換処理群が`ChangeState`群より前にあること。
- `ChangeState`、移動、速度増減などが`command`を直接参照していないこと。
- StateDef `-1`以外のTriggerに`command`が存在しないこと。
- `triggerall`に`command`が存在しないこと。
- プレイヤー操作とオートメーションが同じ入力・技フラグを利用すること。
- 真になったフラグだけでなく、偽になったフラグも定義した時点で解除されること。
- ビット更新時に同じVarの他のビットが維持されること。
- Var番号とビット割り当てが変数一覧および実装で一致すること。
