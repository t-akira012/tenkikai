# オートメーション規約

## 用語と責務

WinMUGENのキャラクター自動操作モードを、このリポジトリでは「オートメーション」と表現する。

この文書は、オートメーションの有効化、入力元の切替、入力ビットへの反映方法を定める。個別の行動判断は、距離、位置、State、時間などを用いてオートメーション中に行う。行動ごとの具体的な判断条件は、この文書へ集約せず、確定した時点で`docs/automation/`配下へ作成する。

## WinMUGENのCPU操作と`command`

WinMUGENのCPUモードでも`command`は入力されるが、その内容はランダムであり、キャラクターの自動運用に必要な判断としては使用できない。

このため、オートメーション中は`command`を読み取らない。距離、位置、State、時間などによる判断結果を入力ビットへ設定し、技遷移、移動、速度増減などの処理は入力元を区別せず、その入力ビットをTriggerとして使用する。

## 自動運用フラグ

自動運用フラグには、入力ビットフィールド`var(2)`の最上位ビットであるビット31を使用する。マスク値は`-2147483648`である。

- オートメーション無効：`(var(2)&-2147483648)=0`
- オートメーション有効：`(var(2)&-2147483648)!=0`
- オートメーションを有効化：`var(2)|-2147483648`

`var(2)`は32ビット符号付き整数であり、利用可能範囲は`-2147483648`から`2147483647`までである。ビット31が立つと値全体は負数になるため、正負や合計値ではなく、必ず上記のビット演算で自動運用フラグを判定する。

## StateDef `-2`での有効化

StateDef `-2`の最上部に、次のControllerを置く。

```cns
;; 自動運用フラグ 利用したい場合は trigger1=1 に指定

[state ]
type=varset
triggerall=!ishelper
trigger1=0
trigger2=palno=[6,12]
var(2)=var(2)|-2147483648
ignorehitpause=1
```

既定では`trigger1=0`として常時有効化を使用せず、パレット番号`6`から`12`までの場合だけ`trigger2`で有効化する。利用者が常にオートメーションを使用する場合は`trigger1=1`へ変更する。`triggerall=!ishelper`により、本体の入力ビットフィールドだけを更新する。

## 入力元の切替

StateDef `-1`は毎tick、`var(2)`の最上位ビットを維持し、下位の入力ビットを解除する。

```cns
var(2)=var(2)&-2147483648
```

各入力ビットは、通常操作とオートメーションの条件を同じ`VarSet`へ記述できる。通常操作では自動運用フラグが立っていない場合だけ`command`を読み、オートメーションでは自動運用フラグが立っている場合だけ自動判断を読む。

```cns
[state ]
type=varset
trigger1=(var(2)&-2147483648)=0
trigger1=command="COMMAND_NAME"
trigger2=(var(2)&-2147483648)!=0
trigger2=オートメーションの判断条件
var(2)=var(2)|MASK
```

同じ番号のTriggerはAND、異なる番号のTriggerはORとして評価される。この構成により、通常操作とオートメーションの入力元を排他的に切り替えながら、どちらも同じ入力ビットを立てる。

個別の自動判断をまだ実装していない入力では、`trigger2`を推測で追加しない。通常操作側の`trigger1=(var(2)&-2147483648)=0`を必須とし、オートメーション中にランダムな`command`が入力ビットへ変換されることを防ぐ。

## 技遷移のオートメーション対応

オートメーション中は、技・移動の遷移処理において`ctrl=0`を使用する。したがって、オートメーション時に成立させる遷移の条件として、`ctrl`をTriggerへ使用してはならない。

すべての技・移動の遷移は、オートメーション操作と通常操作を同じ`ChangeState`へ記述する。両経路に共通する状態、位置、入力対象などの制約は`triggerall`へ記述し、入力元ごとの成立条件は`trigger1`と`trigger2`へ分ける。

```cns
[state ]
type=changestate
value=対象State

; オートメーションと通常操作に共通する制約
triggerall=共通する状態または位置の条件

; オートメーション遷移
trigger1=(var(2)&-2147483648)!=0
trigger1=オートメーションの入力ビットまたは判断条件

; 通常操作遷移
trigger2=(var(2)&-2147483648)=0
trigger2=通常操作の入力ビット
trigger2=ctrl
```

同じ番号のTriggerはAND、異なる番号のTriggerはORとして評価される。`triggerall`へ`ctrl`を記述すると、オートメーション経路も`ctrl=0`によって不成立になるため、共通制約へ`ctrl`を含めてはならない。

オートメーション経路は自動判断によって設定された入力ビットまたは状態情報だけで成立させ、通常操作経路では必要に応じて`ctrl`を使用する。

## 処理順序

入力とオートメーションに関する処理は、次の順序を維持する。

1. StateDef `-2`の最上部で自動運用フラグを設定する。
2. StateDef `-1`の先頭で、自動運用フラグを維持したまま下位の入力ビットを解除する。
3. 通常操作またはオートメーションの一方から、下位の入力ビットを設定する。
4. 入力ビットを参照する`ChangeState`、移動、速度増減などを実行する。

StateDef `-1`のビット変換処理群は、変換後のビットを参照する`ChangeState`群より前に置く。入力ビットのVar番号、下位ビットの割り当て、Command名は[入力ビットマップ](AGENTS.input-map.md)に従う。

## 実装確認

オートメーションに関する変更後は、次を確認する。

- StateDef `-2`の最初のControllerが自動運用フラグを設定していること。
- StateDef `-1`の入力ビット解除がビット31を維持していること。
- すべての`command`変換に、自動運用フラグが立っていない条件があること。
- 自動判断が、自動運用フラグが立っている場合だけ入力ビットを設定すること。
- 技遷移、移動、速度増減などが`command`を直接参照しないこと。
- ビット更新時に`var(2)`の他のビットを維持していること。
- 個別の自動判断と実装が`docs/automation/`配下の対応文書と一致すること。
