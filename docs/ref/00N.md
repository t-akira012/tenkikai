# 00N構造分析

## 調査目的

00Nは、Rootと複数の常駐Helperを重ね、本体そのものを重力球に近い存在として描画するキャラクターである。本稿では、黒い球体の内部運動、残像、回転、拡縮、周辺粒子および浮遊をどのように分担しているかを分析し、TENKIKAIの重力球Helperを改善する際の参考事項を整理する。

調査対象はTENKIKAIディレクトリから相対パスで次のキャラクターディレクトリである。

```text
../00N
```

本稿は構造分析リファレンスであり、00NのState番号、変数番号、素材および処理をTENKIKAIの仕様として定めるものではない。

## 全体構成

`00N.def`は、Root用の複数のCNSに加えて、常駐Helperごとの処理を分割して読み込む。試合中の外観と挙動はRoot単体では完結せず、Rootと複数の常駐Helperの合成によって成立する。

初期化処理は、Player型のHelperを少なくとも5体生成する。StateDef `-2`は各HelperをIDで識別し、それぞれの管理Stateへ送る。

| Helper ID | 主な管理State | 読み取れる役割 |
| --- | --- | --- |
| `2` | 入力・状態管理系 | 入力、状態遷移、防御処理などをRootの外側から補助する |
| `3` | `300000`番台 | 本体に付随する演出または攻撃表示を担う |
| `4` | `400000`番台 | Helper 3とは別系統の付随演出または攻撃表示を担う |
| `5` | `500000`番台 | 球体の内部運動、回転、拡縮、残像、粒子など、重力球的な主要表示を担う |
| `9` | `900000`番台 | 移動、上下浮遊および攻撃時の運動を統合して管理する |

Helper 2、3、4の名称は、処理内容から整理した推論を含む。Helper 5と9は、本件で参照する重力球表現と浮遊運動の中心である。

## Helper 5による球体表示

### 管理Stateと表示Stateの分離

StateDef `500000`は、Helper 5の状態を用途別の表示Stateへ振り分ける。StateDef `500001`は変数、ExplodおよびAfterImageを消去し、次の表示へ移るための初期状態を作る。

球体表示は一つのControllerで黒く塗り潰す方式ではない。次の要素を同じHelper内で段階的に組み合わせている。

- Sprite自身の内部アニメーション
- `AngleDraw`による継続回転
- 時間に応じた拡大または縮小
- 選択された区間だけに適用するAfterImage
- `PalFX`による色調変化
- `BgPalFX`による周囲の暗転
- 複数Explodによる収束粒子

この構造により、黒さ、内部運動、外周の時間的な厚み、周囲の光量変化を別々に制御している。

### 回転と拡縮

StateDef `501000`は表示系列を選び、回転方向、再生方向、色調などをビット値へ記録する。表示系列は`501100`から`501632`まで複数用意され、同じ球体でも異なる内部模様を選択できる。

StateDef `501099`と`501100`は、球体を収縮または膨張させる対になる処理を持つ。

- 回転方向は保持したビットにより正転と逆転を切り替える。
- 収縮側は、経過時間に比例して描画倍率を下げる。
- 膨張側は、経過時間に比例して描画倍率を上げる。
- アニメーション系列の境界で次のActionへ移り、内部模様を連続して変化させる。

したがって、視覚上の呼吸は単なる上下移動ではなく、内部模様の変化、回転および径の変化を同時に見せることで作られている。

### AfterImageの役割

主要な膨張・収縮Stateでは、AfterImageは常時かつ一様には使用されない。特定のActionに限って長めの残像を有効にし、表示の境界に時間的な厚みを加えている。

特に中心的な表示では`trans = none`を用い、Sprite内部の明暗と模様を保持する。AfterImageだけで球体を暗くしようとはしていない。暗さはSprite、色調整および背景暗転で作り、AfterImageは回転や変形の履歴を見せる役割を持つ。

これは、暗い合成を本体と残像へ重ね過ぎると内部運動が失われ、単なる黒い円に見えることを示している。

## 黄金角による収束粒子

StateDef `500020`および`500021`は、黄金角を用いて粒子の初期位置を分散させる。

```text
angle = index * 137.509549 degree
x = angle * cos(angle)
y = angle * sin(angle)
```

生成した座標へ一定倍率を掛けてExplodを配置し、座標と反対方向の速度および加速度を与える。これにより、粒子は四方向の固定位置から直進するのではなく、球体の周囲へ偏りなく現れ、曲線的に中心へ引き込まれる。

この処理の視覚的な意味は次の通りである。

- 黄金角によって、少数の粒子でも規則的な十字配置を避ける。
- 初期位置を半径と角度から決め、球体の周囲へ発散して見える分布を作る。
- 初期座標と反対向きの速度で、中心へ向かう流れを作る。
- 同方向の加速度を加え、重力に引かれるような収束感を強める。

00Nでは、粒子の空間分布と中心への運動が、球体を単なる画像ではなく周囲へ作用する存在に見せている。

## Helper 9による浮遊

StateDef `900000`は、上下方向の補正値を時間区間ごとに増減させる。補正量は一方向へ固定せず、上昇区間と下降区間を繰り返す。

この運動は大きな跳躍ではなく、表示位置へ微小な変化を継続して与える。静止中にも完全停止を避けることで、球体が空間へ固定された画像ではなく、常に浮力または場の揺らぎを受ける物体として見える。

## TENKIKAIの重力球へ応用できる事項

00Nから参照すべきなのは個別のState番号ではなく、表現要素の分担である。

1. 球体本体の内部アニメーションを視認できる明度で残す。
2. 暗さを本体の減算合成だけへ集中させず、色調、外殻、必要に応じた周辺暗転へ分ける。
3. AfterImageは黒塗りの手段ではなく、回転と変形の時間的な履歴として使う。
4. 回転、緩やかな拡縮、微小な上下動を重ね、停止中にも完全静止させない。
5. 周辺光は固定した少数点の直線運動ではなく、角度と半径を変えながら生成する。
6. 重力表現では、粒子を中心方向へ加速させるか、中心の周囲を回りながら収束させる。
7. 前面と背面の描画優先度を分け、粒子が球体の周囲を回っている奥行きを作る。

現在のTENKIKAI重力球を調整する場合、Sprite `18552`の内部アニメーションを潰さず、本体、暗い外殻、AfterImage、Sprite `18553`の周辺光を別の視覚責務として調整するのが適切である。

## そのまま移植しない事項

- 00N固有の巨大なState番号とHelper ID
- 00N固有の変数割り当て
- Rootと常駐Helperを前提とした入力・防御・攻撃管理
- 00NのSpriteおよびAction番号
- 画面全体を暗転させる`BgPalFX`の強度と適用期間
- キャラクター固有の不具合対策、環境依存処理および防御処理

TENKIKAIでは、既存のHelper予約、変数規約、演出設計および実機検収結果を優先し、必要な表現原理だけを採用する。
