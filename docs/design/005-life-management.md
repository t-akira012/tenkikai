# 005: ライフ管理方式

## 動作モデル

TENKIKAIは、原作作品における特殊な強者として、宇宙的で極めて頑強な肉体と非常に硬質な外殻を持つ。この外殻によって一般的な攻撃がほとんど通用しない存在感を、ゲーム上ではHelper Armor式のライフ管理によって表現する。

AIRファイルでは、`the_controller`用Action以外から当たり判定をすべて除去する。本体と常に重なる`the_controller`だけが当たり判定を持ち、相手の攻撃を受ける。攻撃は`the_controller`へ命中するが、Helper Armorによって直接のライフ減少を無効化し、攻撃が持つダメージ情報だけを本体へ渡す。

本体は受け取ったダメージ情報から仮想的な被害量を決定し、自身のライフを減算する。この間も攻撃の直接的な対象は`the_controller`であり、本体そのものは当たり判定を持たない状態を維持する。この構造は硬質な外殻をゲーム上で表現するための方式であり、原作設定として攻撃が肉体へ届かないことを意味しない。

`the_controller`は本体の外殻を代理するため、相手との位置衝突では相手を押し返す。攻撃のダメージを無効化することと、位置衝突を無効化することは別であり、相手が`the_controller`をすり抜ける状態は採用しない。

ダメージを一度受け付けた後は、その攻撃のダメージ値に応じた無敵期間を設ける。無敵期間中に連続して接触する攻撃から追加ダメージを受けず、値が大きい攻撃ほど次のダメージ受付までの間隔を持たせる。これにより、多段攻撃による過剰なライフ減少を避けながら、一撃の重さを受付間隔にも反映する。

ライフが減少した場合は自動リジェネレーションを行う。さらに低ライフ時は、Helper Armorが取得したダメージを本体へ反映する段階で減衰させる。ライフ減少に対して再生とダメージ耐性が重なって強く働くことで、追い詰められてからも容易には倒れないTENKIKAIの頑強さを表現する。

## ダメージ処理の流れ

1. 相手の攻撃が、本体へ追従する`the_controller`の当たり判定へ命中する。
2. `the_controller`は`HitOverride`によって直接のダメージを受けず、`GetHitVar`から攻撃のダメージ値を取得する。
3. 取得したダメージ値を、`the_controller`自身のダメージ保持用Varへ保存する。
4. 次のフレームに、本体が`the_controller`のダメージ保持用Varを読み取る。
5. 本体は低ライフ時の減衰を適用したダメージを、負の`LifeAdd`として自身へ反映する。
6. 本体が値を読み取った後、`the_controller`のダメージ保持用Varを初期化する。

ダメージ保持用Varの初期化は、本体による読取りより前に行ってはならない。命中フレームで保存した値を次のフレームまで維持し、本体のライフ減算へ一度だけ使用してから解除する。

## ダメージ受付間隔

`the_controller`は無敵期間用Varを持つ。ダメージを受け付けたとき、取得したダメージ値に基づいて1以上の時間を設定する。設定後は1tickごとに値を1ずつ減らし、0になった時点で次のダメージを受け付ける。

無敵期間用Varが0より大きい間は、新たな攻撃が`the_controller`へ接触しても、そのダメージを保持用Varへ保存せず、本体ライフへ反映しない。無敵期間は絶対時刻との比較ではなく、残り時間を減算するタイムカウント方式で管理する。

## 自動リジェネレーションと低ライフ耐性

本体ライフが減少した場合は、現在ライフに応じて自動リジェネレーションを行う。リジェネレーションはHelperが直接ライフを変更するのではなく、本体側のライフ管理処理として適用する。

低ライフ時は、`the_controller`から受け取ったダメージ値をそのまま減算せず、さらに減衰させてから本体へ適用する。ダメージ減衰はHelper Armorが取得する元のダメージ情報を失わせず、本体へ反映する最終値を調整する。

リジェネレーションの開始条件、回復速度、上限、および低ライフと判定する閾値と減衰率は、試験実装値から実機上の倒しにくさを確認して確定する。

## 当たり判定と追従

AIRファイル内の全Actionから当たり判定を除去し、`the_controller`用Actionだけに当たり判定を設定する。`the_controller`には、Helper IDと同じ番号のActionを用意し、そのActionへ旧`Begin Action 0`と同一の当たり判定を設定する。

`the_controller`は本体の位置、向き、および当たり判定の基準となる表示状態へ常に追従する。Helperがオーラバウンド用の個別StateDefへ遷移している間も追従とHelper Armorを停止させず、相手から見た攻撃対象を常に本体の位置へ維持する。

## `the_controller`の複数処理

`the_controller`は、Helper Armor式ライフ管理とオーラバウンドを同居させる常駐Helperである。複数の挙動を単一のStateDefへ混在させず、[ADR 006](../ADR/006-controller-routing.md)で定めた共通IDルーティングと挙動別StateDef遷移を使用する。

`the_controller`のIDは`99004`とする。ライフ管理を別Helperへ分離せず、オーラバウンドを管理する同じHelperへ統合する。

```text
the_controller
  ├─ 常時処理
  │    ├─ 本体への追従
  │    ├─ HitOverrideの維持
  │    ├─ ダメージ情報の保持と解除
  │    └─ 無敵期間のカウントダウン
  ├─ ライフ管理
  │    ├─ 本体へのダメージ反映
  │    ├─ 低ライフ時のダメージ減衰
  │    └─ 自動リジェネレーション
  └─ オーラバウンド
       ├─ 技ごとのバウンド定義
       └─ バウンドの共通消費と進行
```

常時性が必要な追従、攻撃受付、ダメージ転送、無敵期間管理は、オーラバウンドのStateDef遷移によって中断されない場所へ置く。オーラバウンドの個別処理は、規定どおり次フレームのStateDef `-2`から共通IDルーティングを経由して復帰する。

## 実装方式

Helper Armorには、`the_controller`による`HitOverride`を使用する。命中時のダメージ値は`GetHitVar(damage)`から取得し、Helper自身の通常変数へ保存する。本体は次のフレームにHelperリダイレクトで値を取得し、`LifeAdd`へ負の値として渡す。

ライフ管理で追加するダメージ保持用`var(11)`と無敵期間用`var(12)`は、オーラバウンドが使用しているVar/FVarと共有しない。現在の割り当ては[変数一覧](../state/var-list.md)に記録する。

## 確定済み設計条件

### Helper Armor

- 攻撃受付対象：`the_controller`
- Helper ID：`99004`
- 防御方式：`HitOverride`
- ダメージ取得：`GetHitVar(damage)`
- 本体への反映：次のフレームに負の`LifeAdd`
- ダメージ保持値の解除：本体が読み取ったフレームに初期化

### 当たり判定

- AIRファイル：`the_controller`用Action以外の当たり判定をすべて除去
- `the_controller`のAction番号：Helper IDと同じ`99004`
- `the_controller`の当たり判定：旧`Begin Action 0`と同一
- `the_controller`の位置衝突：有効。相手を押し返す
- 追従対象：本体

### 無敵期間

- 管理方式：残り時間を保持する通常変数
- 初期値：取得したダメージ値に基づく1以上の値
- 更新：1tickごとに1減算
- 次のダメージ受付条件：残り時間が0

## 未確定の調整値

### 無敵期間

- ダメージ値から無敵期間へ変換する式
- 無敵期間の上限

### 自動リジェネレーション

- リジェネレーションを開始するライフ条件
- 1tickあたりの回復量
- 回復開始までの待機時間
- 回復可能なライフ上限

### 低ライフ時のダメージ減衰

- 低ライフと判定する閾値
- ダメージ減衰率
- 最低適用ダメージ

## 試験実装値

### ダメージ保持

- ダメージ保持用変数：`the_controller`の`var(11)`
- 無敵期間用変数：`the_controller`の`var(12)`
- ダメージ保持期間：命中フレームから次のフレームに本体が読み取るまで

### 無敵期間

- 初期値：`GetHitVar(damage)`と同じtick数
- 減算量：1tickごとに`1`
- 上限：なし

### 自動リジェネレーション

- 開始条件：本体が生存中、ライフが最大ライフ未満であり、そのtickに保留ダメージを反映しない場合
- 回復量：1tickごとに`1`
- 回復開始までの待機時間：なし
- 回復上限：最大ライフ

### 低ライフ時のダメージ減衰

- 低ライフ条件：本体ライフが最大ライフの`1/4`以下
- 適用ダメージ：取得ダメージの`1/2`を整数化
- 最低適用ダメージ：`1`
