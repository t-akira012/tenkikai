# 共通エフェクト設計・実装規約

## 適用範囲

本規約は`docs/design/effect/`で管理する共通エフェクトの設計、StateDef、Helper、Explod、Projectile、変数および文書へ適用する。上位規約は[設計文書の記述規則](../AGENTS.md)と[エフェクト作業規則](../../AGENTS.effect.md)に従う。

## 1000番単位の予約範囲

Helperを使用する各共通エフェクトへ、`500000`以降のStateDefを1000番単位で予約する。

```text
500000〜500999  一つの共通エフェクト
501000〜501999  次の共通エフェクト
502000〜502999  次の共通エフェクト
```

個別エフェクトの予約範囲、Helper IDおよびStateDef割り当ては、対応する個別設計文書で管理する。他のエフェクトの予約範囲を使用しない。

## 大項目・用途別パターン・共通モデル

一つの1000番予約範囲を所有する共通エフェクトを「大項目」とする。大項目の中で、使用場面ごとに異なる調整値を保存する末尾`000`〜`899`のStateDefを「用途別パターン」とする。全用途別パターンが通る実行、管理および終了処理を、一つの論理的な「共通モデル」とする。

同じ大項目に属する用途別パターンの違いは、用途別出現StateDefが保存する変数値だけで表す。色、素材、時間区間、補間、倍率、速度などの調整値が異なることを理由に、用途別の実行モデルを追加してはならない。

新しい用途別パターンを既存の変数契約で表現できない場合は、その大項目に属する全用途が利用できる形で変数契約と共通モデルを拡張する。用途番号、Helper IDまたは発出元に応じて別の共通モデルへ振り分けてはならない。

作用対象、管理責務または再利用単位が異なり、一つの共通モデルとして成立しない場合は、既存大項目の用途別パターンとして追加せず、別大項目への責務分割についてユーザーの承認を得る。

## 用途別出現領域

予約範囲の末尾`000`〜`899`は、用途別出現StateDefへ使用する。Rootなどの発出元は、必要な表現に対応する用途別出現StateDefをHelper生成時に選択する。

用途別出現StateDefは、その用途で必要な調整値をHelper自身の`var`・`fvar`へすべて保存し、同じtickに末尾`900`〜`999`の共通実行StateDefへ遷移する。

調整値には、該当する場合に次を含める。

- Action、素材および表示要素の選択値
- 出現時間、維持時間、消滅時間および全寿命
- 初期倍率、予定倍率、終了倍率および補間方式
- 位置、向き、速度、加速度および軌道係数
- AngleDraw角度、回転速度、X・Y倍率、周期、振幅および位相
- 透過、合成、色調、透明度および描画優先順位
- AfterImageの時間、長さ、間隔、色および合成値
- Explod・Projectileの生成間隔、寿命、位置および運動値
- 終了条件および後始末に必要な値

Root変数を引数領域として使用しない。用途別の調整値を共通実行StateDefへ直接記述しない。

## 共通実行領域

予約範囲の末尾`900`〜`999`は、そのエフェクトの全用途で共有する実行・管理・終了StateDefへ使用する。

共通実行StateDefは、用途別出現StateDefが保存した値だけを用いて処理する。用途番号、発出元StateDef、Rootの技状態を参照して調整値を分岐しない。

出現、維持、消滅などの段階は、原則として保存された時間とHelper自身の経過値から共通実行StateDef内で判定する。段階ごとの調整値を直接記述したStateDefへ分割しない。

## 複数の共通StateDef

末尾`900`〜`999`へ配置する共通StateDefは一個に限定しない。エフェクトの構成上必要な場合は複数を使用する。

複数の共通StateDefは、一つの論理的な共通モデルを構成する処理分割として使用する。用途別パターンごとに異なる時間変化、補間または表現モデルを選択するための分岐先として使用してはならない。左右や前面・背面などの構成要素ごとに共通StateDefが異なる場合も、全用途別パターンは同じ構成要素と処理関係を使用する。

次の構成を許可する。

- 左右、前後、前面・背面など、別Helperで描画する要素ごとの共通実行
- 複数Helperが使用する共通寿命更新および終了処理
- 共通座標、速度、AngleDraw、AfterImage、ExplodまたはProjectile処理
- 複数の共通処理を固定順に通すルーティング
- 終了時のExplod除去、Projectile停止およびHelper消滅処理

各共通StateDefの責務と遷移順は個別設計文書およびState文書へ記載する。

## Explodの有限寿命

共通エフェクトが生成するExplodでは`removetime=-1`を使用しない。各Explodへ、演出として意図した有限の`removetime`を必ず設定する。

親Helperへ`bindtime=-1`で追従するExplodは、親Helper消滅後に残存すると、WinMUGENのHelper配列index再利用によって別のHelperへBind先が移る。このため、親と同時に終了する演出ではExplodの有限寿命を親Helperの寿命へ一致させる。

残光、波紋、軌跡などを親Helperより長く表示する演出では、意図する終了時刻までの有限寿命をExplodへ個別に設定する。親Helperより長く表示すること自体は禁止しない。明示的な`RemoveExplod`は、途中終了、状態中断または演出固有の終了処理が必要な場合に使用する。

## 表現を保った構造変更

既存エフェクトを本規約へ移行する場合、ユーザーが確認した見た目、時間、座標、速度、倍率、色、透過、描画優先順位および生成密度を変更しない。直値を変数へ移す際は、移行前後の式と完成値が一致することを確認する。

構造変更と表現調整を同時に行わない。新しい値または補間方式が必要な場合は、構造移行とは別にユーザーの承認を得る。

## 文書化

個別設計文書には、予約範囲、用途別出現StateDef、共通実行StateDefおよび現在の設定値を記載する。`docs/state/`には実際のStateDef、遷移、変数契約、Helper ID、Explod IDおよびProjectile IDを記載する。

個別設計文書のファイル名とH1は、最初に実装した用途別パターンではなく、1000番予約範囲を所有する大項目を表す名称にする。用途別パターンは同じ個別設計文書の小見出しへ並べ、大項目、用途別パターンおよび共通モデルの関係を一か所で確認できるようにする。

実機調整中はCNSまたはAIRだけを変更し、ユーザー検収後に最終値を設計文書とState文書へ反映する。
