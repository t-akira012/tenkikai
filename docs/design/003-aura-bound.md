# 003: Aura Bound

## 動作モデル

各技StateDefが定めた起点で、002で表示しているオーラを一度だけ大きく拡張する。拡張後は通常のオーラ倍率へ戻り、連続的な鼓動とは異なる瞬間的な力の放出を表現する。

拡張幅と通常倍率への復帰速度を調整可能とし、復帰は即時または滑らかな段階変化から選択できる。本体オーラと頭部オーラは同じバウンドを同期して行う。再度発動する場合は、前回のバウンドが完了した後に新たな発動として扱う。

## 用途

技のエフェクトとして使用する。技側からHelperへ演出指示を渡し、攻撃の発生や命中などの瞬間的な力の表現に利用する。

## 状態・処理関係

002のオーラ表示を基礎とし、各技StateDefが決めた起点を発動点とする。`the_root_monitor` がRootのStateDefと進行を監視し、技ごとの定義に従って単発バウンドを開始する。拡張、保持、復帰の進行状態は本体と頭部へ同じように適用する。

技ごとのバウンド起点、発動タイミング、拡張幅、保持、復帰速度は、Rootの技StateDefに対応する監視分岐として `the_root_monitor` 側で決定する。親の技StateDefにはオーラバウンド用の記述を追加しない。

## 実装方式

Rootから生成した `the_root_monitor` が、バウンド用のVar/FVarを自身で管理する。`the_root_monitor` はRootのStateNoと技StateDefの進行を監視し、各技の定義に従って発動する。

常時監視側は、技ごとの監視分岐によるバウンド定義、バウンド消費と進行を処理し、本体オーラと頭部オーラへ同じ進行状態を渡す。

実装構造の記述イメージ：

```text
the_root_monitor
  ├─ Root StateNo = 技A && private-time = 起点
  │    └─ 技A用バウンドを定義
  ├─ Root StateNo = 技B && private-time = 起点
  │    └─ 技B用バウンドを定義
  └─ 共通処理
       ├─ バウンド消費
       ├─ 拡張量の更新
       ├─ 復帰処理
       └─ 本体・頭部オーラへ同期
```

親の技StateDefにはオーラバウンド用の記述を追加せず、技ごとの監視とバウンド定義は `the_root_monitor` 側に集約する。

テストではStateDef `4001`への移動でバウンドを発動する。

## テスト設定（暫定）

### 発動条件

- 各技StateDefが定めた起点を `the_root_monitor` が検知
- テスト用StateDef：`4001`

### バウンド制御

- 発動フラグ：変数で制御
- 拡張幅：通常オーラの5倍（動作確認用）を基準に変数で制御
- 復帰速度：変数で制御
- 通常倍率への復帰：復帰速度に応じて即時または段階的に実行
