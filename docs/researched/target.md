# Target

## Targetスロット

ユーザー調査では、Targetは1～8の8個のスロットで管理される。

- 新しいTargetには、最も若い空きスロットが割り当てられる。
- 割り当て後にスロット番号は入れ替わらず、繰り上がらない。
- Targetを失うと、そのスロットが空きになる。
- Targetリダイレクトは、該当するTargetのうち最も若いスロットを参照する。
- TargetIDを指定した場合も、該当するTargetIDの中で最も若いスロットを参照する。

## Targetの喪失と保持

ユーザー調査では、次のTarget喪失挙動が確認されている。

- Target側が `MoveType!=H` になると、通常はTargetを失う。
- Target側がStateNo `5150`（死亡ステート）になると、Targetを失う。
- Targetを取得している側が攻撃を受けた場合、または死亡した場合もTargetを失う。
- 攻撃を受けた判定より後に別の攻撃が命中した場合は、後の命中によるTarget取得が成立することがある。
- `ReversalDef` の永続ターゲットは、通常の喪失条件の例外である。

複数Targetが存在する場合、最も若いTargetスロットの相手が外れない間は、他のTargetが `MoveType!=H` になってもTargetを失わない保持バグが発生することがある。この挙動は追加検証が必要である。

## TargetとHitID

Targetを取得している相手自体は攻撃側が管理するが、`Target(ID)` で参照するHitIDは被攻撃側が管理する。そのため、複数の攻撃が命中した場合でも、被攻撃側が保持するHitIDは単一であり、攻撃側が意図したHitIDと一致しない相手へHitID条件が反応する場合がある。

タッグ戦で味方側の別キャラクターが同じHitIDを使用すると、Targetを取得している相手を識別する条件が混同することがある。

## MoveHitとMoveGuarded

同時にヒットとガードが発生した場合、`MoveHit` と `MoveGuarded` の両方ではなく、後側に処理された方が基準になることがある。新規Targetへの同時ヒットでは、Targetリダイレクトで参照する側と参照しない側の状態が基準になる。

この挙動は `MoveHit`、`MoveGuarded`、`HitCount`、攻撃側の硬直処理にも影響する。

## HitCountとの関係

味方側の本体またはHelperのいずれかがTargetを保持している間は、画面に表示されるヒットカウントがリセットされない。味方側にTargetを保持する本体またはHelperが存在しない場合、ヒットカウントがリセットされる。

Helperの消失に伴うヒットカウントのリセットについては、追加検証が必要である。

## Helperを対象とするTargetState

相手Helperに対する `TargetState` は、相手Helperがガード以外の被弾状態であるか、`ReversalDef` が成立している場合に影響を与えられる。相手本体には、ガード状態でも影響を与えられる。

## TargetリダイレクトとTarget系Controllerの不具合

Target系Controllerのパラメータ内で `Target` リダイレクトを直接使用すると、フリーズまたはエラー終了することがある。Target情報を使用する場合、いったんVarへ代入してからパラメータへ渡す方法で回避できるという調査結果がある。

## 未検証事項

- `HitOnce=0` の同時命中時における対象選択が、Targetリダイレクトのスロット順に従うか。
- Target保持バグの再現条件と、別のTargetが保持される正確な条件。
- Helper消失時のヒットカウントリセット条件。
