# Variables

## Var（Variable）

Varは、中に数値を入れて別の場所で取り出せる情報である。特殊な情報の管理や数値計算に利用する。単純にVarと呼ぶ場合は、`Var()` というトリガーではなく変数自体を指す。変数への代入は、変数へ新しい情報を入れることである。

例えば、`VarSet` で `var(23)` に `230` を代入すると、数値情報として `var(23)` を記述した場所で `230` が返る。新しく代入すれば、新しく代入した数値が返る。`var(23)<300` という条件式は、`var(23)` の値が300未満なら真、300以上なら偽になる。

## Varの種類

### `Var()`

整数型の数値を記録する変数。0番から59番までの60個の変数スロットがある。記録できる値の範囲は、32bit符号付き整数の最小値 `-2147483648` から最大値 `2147483647` までである。

### `FVar()`

浮動小数点型の数値を記録する変数。0番から39番までの40個の変数スロットがある。小数を利用できるが、桁数が多い場合は細かな数値が浮動することがある。

### `SysVar()`・`SysFVar()`

システム用の変数。数値の型はそれぞれ `Var()`・`FVar()` と同じで、0番から4番までの5個ずつ、合計10個のスロットがある。Commonステートで使用されているもの以外は、基本的に利用されない。

通常の `Var` と `FVar` は合計100個、システム用は合計10個である。これらの変数スロットは1キャラクターごとに個別に保有され、プレイヤーキャラクターだけでなくHelperも持つ。各キャラクターの変数は個別管理され、他のキャラクターから干渉されない。

## Var代入

Varを変更できるState Controllerは次のとおりである。

- `VarSet`: 指定した変数へ、指定した数値を代入する。
- `VarAdd`: 指定した変数に、指定した数値を加算代入する。
- `VarRandom`: 指定した変数へ、指定した範囲の数値をランダムに入れる。
- `VarRangeSet`: 指定した範囲の変数へ、指定した数値を代入する。
- `ParentVarSet`: Helperから親の指定した変数へ数値を代入する。
- `ParentVarAdd`: Helperから親の指定した変数へ数値を加算する。
- 演算子 `:=`: 条件式中で行うVarSet。`SysVar` と `SysFVar` には使用できない。

上記以外では、ラウンド持ち越し処理を除いてVarが変動することはない。

## Varのラウンド持ち越し

ラウンドをまたぐと、変数はFile-/CNSファイルにある `IntPersistIndex` と `FloatPersistIndex` の設定値に従って0へリセットされる。

リセット対象は、設定値より小さい番号の変数スロットである。例えば設定値が `30` の場合は、変数 `0`～`29` がリセットされ、変数 `30` 以降は次のラウンドへ持ち越される。

`SysVar` と `SysFVar` は一切持ち越されない。別の試合へ変数を持ち越すこともできない。State ControllerとHelperはラウンド終了時点で消去されるため、それらが保持する変数を持ち越すこともできない。

## 記述例

次の例では、起き上がりステートで変数を0に戻し、毎フレーム1ずつ加算する。これにより、起き上がり後から次の起き上がりまでのフレーム数を変数で確認できる。

```ini
[State -3]
Type = VarSet
Trigger1 = StateNo = 5120
var(21) = 0

[State -3]
Type = VarAdd
Trigger1 = 1
var(21) = 1
```

## 補足

変数は、制作中に管理したい特定の情報に利用する。変数スロットを指定する引数部分は数値として認識されるため、算式や条件式を加えることもできる。例えば、特殊な管理では `VarSet(var(0)+(Enemy,ID!=EnemyNear,ID))` のような指定が利用されることがあるが、基本的な管理には使用しない。

## 注意点

- 変数スロットが重複すると、条件式が正しく動作しなくなるため、使用スロットを表などで管理する。
- 変数スロットは通常の `Var` と `FVar` を合わせて100個しかないため、無計画に使用すると不足する。
- 使用数を抑えるには、`Floor()` などを利用した桁数分割管理や、bit演算によるbit桁数分割管理を利用する。

## TempVar

一時的に使用する変数としてTempVarを用意すると、細かな変数処理をまとめられる。2～3個を用意しておくとよい。

TempVarには次の用途がある。

- 該当State Controllerでのみ使用する計算補助用TempVar
- 該当フレームでのみ使用する条件式補助用TempVar
- 該当ステートで使い続ける処理補助用TempVar

前二者は別々の場所であれば同じ変数スロットを使い回せる。複雑な計算式ではVarへ入れないと使えない場合があり、TempVarが役立つ。最後の用途は別々のステートであれば同じ変数スロットを使い回せる。CommonステートでのSysVarは、これらの用途で使われる。
