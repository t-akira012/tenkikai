# 技仕様の解決手順

## 自然言語から解決済み仕様まで

1. ユーザーの自然言語要求を意味を変えずに記録する。
2. 技を通常技、対空、突進、飛び道具、投げ、当て身、超必殺のいずれかへ分類する。複合技は複数指定してよい。
3. `common-v1`を適用する。
4. 分類プロファイルを適用する。
5. ユーザー指定で該当項目を上書きする。
6. TENKIKAI固有規約との整合を確認する。
7. 承認必須項目をユーザーへ提示する。
8. 全項目を解決し、演出と攻撃定義の同期を確認してから実装へ進む。

## 解決状態

| 状態 | 意味 |
| --- | --- |
| デフォルト適用 | 版付きデフォルトの値または挙動を採用する |
| ユーザー指定 | 自然言語要求によってデフォルトを変更する |
| 対象外 | 技の構造上、その項目を持たない |
| ユーザー承認済み | 危険性、特殊性または互換性制約を説明し、承認を得た |

解決済み仕様では、値とともに解決状態を記録する。承認必須項目に「デフォルト適用」を使用してはならない。

## デフォルトの継承

```text
common-v1 < 分類プロファイル-v1 < ユーザー指定
```

複数の分類プロファイルを使う場合は適用順を個別技文書へ明記する。同じ項目が競合する場合は、ユーザー指定がなければ承認を得る。

プロファイルを改訂するときは`v2`として追加し、既存技が参照する`v1`を書き換えない。ただし誤記修正は、根拠と影響範囲を確認したうえで同一版を修正してよい。

## KFM値の扱い

KFMの数値は`../kfm/kfm.cns`の対応StateDefから採る。KFMのAIRに依存する次の値は、分類プロファイルだけでは確定しない。

- 発生tick
- 攻撃判定の持続tick
- 後隙tick
- Clsnの座標と大きさ
- Actionの総時間

これらはTENKIKAIのActionと表現設計から個別に解決する。

## 差異の扱い

個別技文書、`docs/design/`、`docs/state/`、CNSまたはCMDに差異がある場合は、自動同期しない。差異の値、条件、StateDef、成立経路を提示し、ユーザーが指定した正本へ合わせる。
