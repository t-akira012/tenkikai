# 技仕様の解決手順

## 自然言語から解決済み仕様まで

1. ユーザーの自然言語要求を意味を変えずに記録する。
2. 技を通常技、対空、突進、飛び道具、投げ、当て身、超必殺のいずれかへ分類する。複合技は複数指定してよい。
3. 既存の確定事項とユーザー要求から決まらない項目をすべて列挙する。
4. 未確定事項をユーザーへ質問する。
5. 試験実装が目的の場合に限り、版名、適用項目および具体値を示してデフォルト候補の採用可否を質問できる。
6. ユーザーが明示承認した試験値だけを採用する。Powerの試験値は独立した項目として提示し、承認を得る。
7. TENKIKAI固有規約との整合を確認する。
8. 承認必須項目をユーザーへ提示する。
9. 全項目を解決し、演出と攻撃定義の同期を確認してから実装へ進む。

## 解決状態

| 状態 | 意味 |
| --- | --- |
| ユーザー指定 | 自然言語要求によって値または挙動を確定する |
| 対象外 | 技の構造上、その項目を持たない |
| ユーザー承認済み | 提示した試験値、危険性、特殊性または互換性制約について承認を得た |

解決済み仕様では、値とともに解決状態を記録する。未確定事項は推測またはデフォルト候補で補わず、必ずユーザーへ質問する。回答がない項目を採用してはならない。

Powerの消費、増加、取得、相手への付与および固定は、ユーザーが具体値を指定するか、独立して提示された試験値を明示承認した場合だけ解決済み仕様へ記録する。未承認の場合は分類プロファイルまたはKFMの値を採用せず、「なし」も補わない。

## デフォルト候補

`common-v1`、分類プロファイルおよびKFM値は、ユーザーへ試験実装用の候補を提示するためだけに使用する。自動継承しない。

候補を提示する場合は、版名、適用項目および具体値を示す。ユーザーが明示承認した範囲だけを「ユーザー承認済み」の試験値として採用し、確定値と区別する。

複数の分類プロファイルを候補として提示する場合は、適用順と競合項目を示してユーザーの選択を得る。

プロファイルを改訂するときは`v2`として追加し、既存技が参照する`v1`を書き換えない。ただし誤記修正は、根拠と影響範囲を確認したうえで同一版を修正してよい。

## KFM値の扱い

KFMの数値を試験候補として提示する場合は、`../kfm/kfm.cns`の対応StateDefから採る。KFMのAIRに依存する次の値は候補としても確定せず、ユーザーへ質問する。

- 発生tick
- 攻撃判定の持続tick
- 後隙tick
- Clsnの座標と大きさ
- Actionの総時間

これらはTENKIKAIのActionと表現設計から個別に解決する。

## 差異の扱い

個別技文書、`docs/design/`、`docs/state/`、CNSまたはCMDに差異がある場合は、自動同期しない。差異の値、条件、StateDef、成立経路を提示し、ユーザーが指定した正本へ合わせる。
