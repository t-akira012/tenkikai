# ADR 015: the_controller 99004の個別挙動ルーター

## 状態

採用

## 背景

`the_controller`はライフ管理と複数の演出挙動を担当する。処理を一つのStateDefへ集約すると、挙動の判定と実処理が混在し、個別挙動の追加や変更が他の処理へ波及する。

## 決定

`the_controller`は、共通IDルーティング後に監視StateDefを経由し、挙動ごとの個別ルーターと個別挙動StateDefへ分離する。すべての挙動塊は固定された順序で毎tick処理する。個別ルーターは該当する個別挙動を一つ、または0個選択する。個別挙動を実行した場合も、実行しなかった場合も、必ず次の個別ルーターへ渡す。

各個別挙動は、監視、挙動選択、実処理、最終処理の責務を混在させない。各挙動塊は固定された順序で連続する。最後の挙動塊の処理後だけ最終処理を経由して終了し、次フレームの共通ルーティングから通常の監視経路へ戻る。監視StateDefへ直接戻して同じ発動条件を再評価する遷移は行わない。

## 結果

ライフ管理や演出挙動を追加しても、既存の個別処理を一つのStateDefへ集約せずに拡張できる。各挙動塊は互いを排他的に選択する分岐ではなく、固定順で連続して処理される。具体的なHelper ID、StateDef番号、現在の遷移構成は[Helper IDとルーター](../state/helper-99004-the-controller.md)および各StateDef文書で管理する。
