# ADR 022: 常駐Helperの存在を利用側で確認しない

## 状態

採用

## 背景

常駐Helperは、ラウンド中に継続して存在することを前提として、Rootの常時監視から生成および再生成される。常駐Helperを参照する処理が、その都度`NumHelper`で存在を確認すると、常駐しているという前提を利用側でも重複して管理することになる。

存在確認を利用条件へ加えると、本来は常に実行する位置、アニメーション、変数などの参照が条件分岐になり、常駐Helper間の連携を停止させる原因になる。参照先が存在しない場合の代替処理を利用側へ設けることも、常駐性を保証する生成処理と責務が重複する。

## 決定

常駐Helperは常駐しているものとして扱い、常駐Helper番号を指定した`NumHelper`を生成タイミング以外で使用しない。

`NumHelper`による存在確認は、Rootが対象の常駐Helperを生成または再生成するControllerで、同一IDの重複生成を防止するためにだけ使用する。

```cns
trigger1=!ishelper
trigger1=!numhelper(対象ID)
```

生成後の常駐Helperを利用する処理は、`NumHelper`による存在確認を前置せず、必要な常駐Helperを直接参照する。位置、アニメーション、変数、Stateなど、参照内容によってこの規則を変えない。

```cns
helper(対象ID),参照内容
```

常駐Helperが存在しない場合を想定したRoot基準の代替値、別Helper基準の代替値、処理の停止条件を利用側へ設けない。常駐Helperが失われた場合の復旧は、Rootの生成および再生成Controllerだけが担当する。

この決定は常駐Helper番号に対する`NumHelper`へ適用する。技ごとに生成され、寿命や個数を動作条件として扱う非常駐Helperの存在確認は対象外とする。

## 結果

常駐Helperの存在管理はRootの生成処理へ一元化され、利用側は常駐性を前提として直接連携する。存在確認によって追従、同期、監視などが停止する分岐を作らず、常駐Helperの定義と実装上の扱いが一致する。
