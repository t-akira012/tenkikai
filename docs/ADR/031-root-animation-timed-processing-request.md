# ADR 031: 本体アニメーション変更・時間付き処理予約

## 状態

採用

## 背景

Root本体のアニメーション変更に伴う表示処理には、開始StateDefを離れた後も短時間だけ継続するものがある。異形回避の再出現後は16tickで全身の縦長変形を復元し、画面横断突進の再出現後は、異形回避とは概念的に異なる専用モデルで5tickの復元を行う。

これらへ用途ごとの通常変数と要求bitを割り当てると、短い処理を追加するたびに変数領域を消費する。一方、異形回避復帰と突進復帰は同じ表現モデルではなく、時間管理を共通化することを理由に倍率計算まで一体化してはならない。

本体アニメーション変更に伴う処理は、ゲーム上の要請により長くても約5秒である。WinMUGENの約60tick/秒を基準にしても約300tickであり、9bitの0〜511tickで恒久的に収容できる。Helper、背景色、常駐管理など、本体アニメーション変更以外の処理は数十秒以上継続する可能性があるため、この上限を適用できない。

## 決定

### 適用範囲

`the_controller`がRoot本体のアニメーション変更を契機として開始し、Rootが開始StateDefを離れた後も継続する短時間処理だけを、本ADRの時間付き処理予約で管理する。

Helper、Explod、Projectile、背景色変更、全画面色変更、常駐管理、ラウンド単位の処理など、本体アニメーション変更以外の時間管理には使用しない。これらは各責務に必要な長さの時間領域を個別に持つ。

### 予約変数

`the_controller`の`var(9)`を、本体アニメーション変更・時間付き処理予約ビットフィールドとする。

| bit | 用途 |
| ---: | --- |
| 0〜8 | 経過tick、0〜511 |
| 9〜17 | 予約全体tick、0〜511 |
| 18〜22 | 処理type、0〜31 |
| 23〜31 | 未使用 |

処理type `0`は予約なしとする。予約開始時は経過tickを`0`、予約全体tickを指定値、処理typeを用途別の値へ設定する。共通時間処理は経過tickを進め、予約全体tickの最終tickを適用した次の処理周期でbit 0〜22を解除する。上位の未使用bitは、予約登録、更新および解除のすべてで保持する。

予約全体tickは1〜511とする。511tickは約8.5秒であり、最大約5秒とする本体アニメーション変更処理を十分に収容する。

### 処理type

| type | 用途 | 現在の予約時間 |
| ---: | --- | ---: |
| `0` | 予約なし | — |
| `1` | 異形回避再出現後の復帰 | 16tick |
| `2` | 画面横断突進再出現後の復帰 | 5tick |
| `3` | ラウンド終了時接地後の復帰 | 4tick |
| `4`〜`31` | 未使用 | — |

StateDef `302`を観測した場合は`16tick / type 1`、StateDef `1202`を観測した場合は`5tick / type 2`、StateDef `303`を観測した場合は`4tick / type 3`を予約する。将来の対象処理は、`hoge tick / type hoge`として同じ変数契約へ追加する。

### 共通時間処理とtype別モデル

共通化するのは予約登録、経過tick更新、全体tick到達判定、予約解除および進行率を求められる変数契約までとする。

各処理typeの倍率、角度、位置および表示値の計算は、概念ごとに独立したControllerとして実装する。異形回避復帰、突進復帰、ラウンド終了時接地復帰は同じ初期値と終了値を使用していても別モデルとし、一つの数値または式の変更を他へ波及させない。

`var(2)`のbit 4、マスク値`16`は、本体アニメーション変更・時間付き処理が当該tickに有効であることを示す共通要求bitとする。処理typeごとに新しい要求bitを消費せず、type別モデルが同じ完成値経路へ結果を渡す。

## 結果

本体アニメーション変更に伴う短時間処理を追加するとき、通常変数や要求bitを用途ごとに増やさず、予約tickと処理typeだけを追加できる。

時間管理の変数契約は共通化されるが、異形回避復帰と突進復帰の表現モデルは分離される。長時間化し得る非本体アニメーション処理を511tickへ誤って制限することも防止される。
