# ADR 028: the_controllerの同一寿命値をビットフィールドへ集約する

## 状態

採用

## 背景

`the_controller`は複数の完成フラグ、カウンター、ダメージ値を個別の通常変数へ保持していた。通常変数領域には上限がある一方、各値が必要とする数値範囲は小さく、同じ初期化周期を持つフラグも複数存在する。

ただし、初期化周期や保持期間が異なる値を無条件にまとめると、ある値の初期化によって別の値が失われる。集約では値域だけでなく、保持期間と部分更新の契約を一致させる必要がある。

## 決定

オーラバウンドの有効状態と待機tickを`var(0)`へ集約する。有効状態はbit 0、待機tickはbit 1〜15を使用する。開始から終了まで値を保持し、待機tickだけを減算する。

Helper Armorの保留ダメージ、ダメージ受付無敵期間、PlayerPush無効化、Helper Armor無敵を`var(11)`へ集約する。保留ダメージはbit 0〜15、無敵期間はbit 16〜23、二つの完成フラグはbit 24とbit 25を使用する。ダメージは65535、無敵期間は255を上限とする。保持値と毎周期更新フラグは、対象領域だけを部分更新する。

Head系表示、Head Aura非同期、Body系AngleDraw適用を`var(22)`へ集約する。これらはすべて同じ処理周期の先頭で初期化され、その周期内だけ有効な完成フラグである。bit 0〜3を既存の表示制御、bit 4〜7を変換・適用制御へ割り当てる。周期途中で`var(22)`全体を再初期化しない。

本体自由傾斜の残存時間と角速度コードを`var(7)`へ集約する。残存時間はbit 0〜8、角速度コードはbit 9〜15を使用し、bit 16〜31は将来の割当に残す。残存時間の減算では角速度と上位領域を保持し、新しい要求の登録では上位領域を保持したまま下位16bitだけを更新する。

変数番号は詰めない。集約によって未使用となった番号は、将来の割当に利用できる空き領域として残す。

## 結果

前後ダッシュ専用の後方リースに使用していた`var(8)`は未使用へ戻した後、[ADR 030](030-controller-managed-root-screenbound.md)でRoot画面外移動許可booleanへ再割当した。`var(12)`は[ADR 033](033-helper-armor-config-and-damage-attenuation.md)でHelper Armor configへ再割当した。`var(13)`、`var(14)`、`var(17)`〜`var(20)`が未使用である。各ビットフィールドの割当、初期化時期、保持期間、部分更新契約は変数一覧を正本とする。
