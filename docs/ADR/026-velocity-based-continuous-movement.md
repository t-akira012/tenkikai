# ADR 026: 連続運動の速度管理と位置操作の役割分担

## 状態

採用・実機確認済み

## 背景

[ADR 005](005-position-based-movement.md)は、入力解除後に水平速度が残留する問題を避けるため、入力に起因する移動を`PosAdd`で管理し、`Vel`を重力や被弾などの物理挙動へ限定した。

この方式は入力と位置変化を一致させやすい一方で、Controllerが成立しないtickには運動が即座に失われる。移動前の予備動作、StateDef間の移行、移動後の終了動作へ運動を引き継げず、その場へ固定されたような静止を生じやすい。

[動きの連続性](../design/010-continuous-floating-motion.md)では、TENKIKAIを地面へ固定された存在として見せず、予備動作、主動作、終了動作の間も空間内の運動を継続する。位置を毎tick直接加算することを入力移動全体の原則にすると、この表現を実現するたびに各StateDefへ個別の位置加算を複製する必要がある。

ただし、短距離ワープ、出現位置の選択、画面端や接地の補正は、経過時間に応じた連続運動ではなく、位置を瞬時に確定する処理である。これらを速度へ置き換えると、到達までのtick、残留速度、他の物理処理との合成が発生し、本来の位置確定という役割が不明確になる。

## 検討した方式

### 入力移動をすべて位置操作で管理する

入力解除と同時に停止でき、移動量をState Controllerの値として直接把握できる。しかし、状態遷移をまたぐ慣性や加減速を表現できず、移動の連続性を各StateDefの`PosAdd`で再現し続ける必要がある。

### 位置操作をすべて速度へ置き換える

運動の引き継ぎは統一できるが、ワープや出現位置選択にも途中経路と残留速度が生じる。座標を瞬時に確定する処理まで連続運動として扱うため、意図した演出と一致しない。

### 連続運動と位置確定を分ける

時間経過に沿って移動する処理は`VelSet`または`VelAdd`で管理し、瞬間的な移動と位置補正は`PosAdd`または`PosSet`で管理する。運動の連続性と正確な座標確定を、それぞれに適した仕組みで表現できる。

## 決定

時間経過に沿った連続運動には`Vel`を使用する。通常の前後・上下移動、ダッシュ、回避中の移動、ワープ前後の予備・終了動作はこの対象とする。

途中経路を表示せず位置を瞬時に確定する処理には`PosAdd`または`PosSet`を使用する。短距離ワープ本体、異形回避の出現位置選択、画面端補正、接地補正はこの対象とする。

`cns/constants.cns`のデフォルト移動速度は0を維持する。TENKIKAI固有の連続運動は各StateDefまたは常時監視処理で明示し、M.U.G.E.Nの共通歩行・走行速度へ委ねない。

速度を設定する処理と解除する処理を対にする。StateDefをまたいで運動を継続する区間では速度を引き継ぎ、行動終了、方向反転、被弾、接地、位置確定など、運動の意味が変わる地点では、その行動の設計に従って減速または明示的な解除を行う。

StateDef `-3`で水平速度または垂直速度を無条件に初期化しない。入力移動、技固有移動、被弾速度を区別せず消去するためである。

## 期限付きRoot移動要求

継続移動は、個別StateDefからRoot変数へ期限付きの移動要求を発行し、StateDef `-3`が一元的に速度へ反映する。StateDef `-3`は要求元のStateDef番号を判定しない。

Root変数は次の責務で割り当てる。

| 変数 | 責務 |
| --- | --- |
| `var(8)` | 水平移動要求の有効期限 |
| `var(9)` | 垂直移動要求の有効期限 |
| `var(11)` | 水平軸の個別速度処理が共通処理を排除する有効期限 |
| `var(12)` | 垂直軸の個別速度処理が共通処理を排除する有効期限 |
| `var(13)` | 水平目標速度を最低速度として扱うモード |
| `var(14)` | 水平半コサイン減速の残りtick |
| `fvar(1)` | 目標X速度 |
| `fvar(2)` | X加減速度 |
| `fvar(3)` | 目標Y速度 |
| `fvar(4)` | Y加減速度 |
| `fvar(9)` | 水平半コサイン減速の開始X速度 |

有効期限はRootの`private-gametime`である`var(0)`を基準とする。移動を継続する個別StateDefは、毎tick、対象軸の有効期限、目標速度、加減速度を更新する。期限にはRootと常時監視StateDefの実行順を吸収できる短いリースを与える。

StateDef `-3`は、有効期限内であれば現在速度を要求された目標速度へ加減速する。水平要求の最低速度保証モードでは、要求方向へ目標速度未満の場合だけ加速し、目標速度以上の同方向速度は維持する。

水平要求が更新されず期限切れになった場合は、その時点のX速度を開始値として半コサイン曲線で0へ減衰させる。開始時の`abs(Vel X)`が`3`以下なら32tick、`3`を超える場合は16tickとし、選択した時間は減速終了まで変更しない。新しい水平要求では曲線を解除し、現在速度から新しい目標へ加減速する。垂直要求の期限切れ後は、最後に指定された加減速度を使ってY速度を0へ近づける。速度が0へ到達した時点で、その軸の要求値を初期化する。

方向反転時は速度を瞬時に反転させず、現在速度から新しい目標速度へ同じ加減速処理で近づける。このため、速度は`0`を通過してから反対方向へ加速する。

水平と垂直の要求は独立して管理する。一方の軸だけを使用する移動は、他方の要求期限、目標速度、加減速度を変更しない。

## 個別速度処理との境界

期限付きRoot移動要求は、すべての`VelSet`と`VelAdd`を代替する仕組みではない。速度処理を次の責務へ分ける。

| 処理 | 実装責務 |
| --- | --- |
| 通常移動、ダッシュ、回避などの継続移動 | 期限付きRoot移動要求 |
| 一度だけ加える反動、推進、ノックバック | 対象StateDefの個別`VelAdd` |
| 瞬間ワープ時の完全停止 | 対象StateDefの個別`VelSet`と両軸要求の解除 |
| 被弾速度 | M.U.G.E.Nの被弾処理。Root移動要求だけを無効化し、被弾速度を共通処理で上書きしない |
| 瞬間ワープ、出現位置、画面端、接地の補正 | `PosAdd`または`PosSet` |
| 技固有の特殊軌道 | 対象StateDef。通常移動要求と合成するか、排他的に置き換えるかを技ごとに定める |

個別速度処理を追加する場合は、期限付きRoot移動要求との優先関係を明示する。共通処理側へStateDef番号の除外一覧を追加してはならない。個別処理が共通移動を排除する必要がある場合は、対象軸の排他期限を更新してから個別速度を適用する。

近距離ワープの予備動作では進入時の速度を即座に初期化せず、最低速度保証モードを使用せずに前方`1`または後方`-1`へ加減速する。進入前の速度が目標を上回る場合も目標速度へ減速する。瞬間移動の時点でX・Y速度を`0`へ戻し、水平・垂直の要求期限、目標速度、加減速度、最低速度保証モードも解除する。ワープ前の速度は移動先へ持ち越さない。

State奪取中はStateDef `-3`が実行されないが、`private-gametime`はStateDef `-2`で進行する。したがって、State奪取前の移動要求は期限切れとなり、自己Stateへ復帰した後に古い要求を再適用しない。被弾中は移動要求を解除するが、現在の速度は被弾処理へ委ねる。

## 行動ごとに確定する事項

各行動を期限付き移動要求へ移行する際、次を確定する。

- 入力開始時に即座に目標速度へ達するか、加速区間を設けるか
- 入力解除後に即座に停止するか、減速区間を設けるか
- 前後反転時に現在速度を打ち消してから加速するか、目標速度へ直接切り替えるか
- 予備動作、主動作、終了動作の間で速度をどこまで引き継ぐか
- 被弾、ガード、ダウン、勝利、登場などへの遷移時に水平・垂直速度をどう扱うか
- 上下入力による速度と、重力・上部制動・浮遊下限処理をどう合成するか

これらは動きの印象を決めるため、移動種別ごとに実機確認を行い、確定後に設計文書とCNSへ反映する。

## 影響

ADR 005の「入力移動は`PosAdd`、水平速度は常に0」という一律の制約を置き換える。速度残留は`PosAdd`への全面的な回避ではなく、期限付き要求と運動ごとの明示的な開始、引き継ぎ、終了によって防止する。

移行対象は通常の前後・上下移動、空中歩行、高速ダッシュ、近距離ワープの予備・終了動作、異形回避中の連続移動である。瞬間ワープと座標補正は移行対象に含めない。

通常移動、浮遊移動、高速ダッシュ、近距離ワープ、異形回避の連続移動を期限付き要求へ移行し、実機検収を完了した。

新しい移動StateDefが増えても、StateDef `-3`へ番号別の分岐を追加しない。各StateDefが同じRoot移動要求契約を使用するため、共通処理の規模はStateDef数に依存しない。
