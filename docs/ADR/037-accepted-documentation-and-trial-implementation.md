# ADR 037: 検収済み文書と試験実装の分離

## 状態

採用

## 背景

ADR 035はCNSとdocsに差異がある場合、CNSを正本としてdocsを現行実装へ同期すると定めていた。この規則に従うと、実機調整中に何度も変更される値までdocsへ複製される。CNSとdocsの両方を各試行で更新することになり、トークンと保守負担が増える一方、未検収値が設計確定値として誤読される可能性がある。

## 決定

CNS、CMDおよびAIRは現在のコード実装の正本とする。docsはユーザーが指定または承認した要求、検収済みの設計・挙動、およびそれを理解するために必要な実装関係を記録する。

WinMUGEN実機で調整中の値と未検収の挙動はCNS、CMDまたはAIR上で管理し、docsへ複製しない。実機確認の反復ごとにdocsを更新しない。個別技仕様で明示承認された試験候補は、実装要求の一部として記録できるが、実機調整で変更した値へ自動追従させない。

ユーザーが挙動を検収した後、確定した値と挙動を設計文書、技仕様文書、State文書および変数文書のうち必要なものへ反映する。

試験中のCNSとdocsに差異があること自体は不整合とみなさず、自動同期しない。検収済み仕様との差異を検出した場合は、CNSまたはdocsを自動変更せず、差異を報告して指示を待つ。

本決定はADR 035のうち、未検収の試験実装をdocsへ常時同期する規則を置き換える。CNS、CMDおよびAIRがコード実装の正本であることは維持する。

## 結果

- 実機調整中の反復値をCNSとdocsの両方で更新しない。
- docsを検収済みの要求、設計および挙動の記録として保つ。
- 検収後に確定値を必要な文書へ一度反映する。
- 試験中の実装と検収済み文書との差を、誤った同期や巻き戻しの根拠にしない。
