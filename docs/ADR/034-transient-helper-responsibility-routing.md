# ADR 034: 非常駐Helperの責務ビットルーティング

## 状態

採用

## 背景

共通エフェクトを担当する非常駐Helperは、用途別出現StateDefで調整値を保存した後、各エフェクトの共通実行StateDefに留まって表示、運動、周期生成および寿命を更新している。これらがStateDefの`time`を時間基準にする限り、Helperが別のStateDefへ移動すると経過tickがリセットされる。そのため、発光、拡縮、粒子生成、寿命などを継続したまま、別のStateDefが担当する移動や攻撃を合成できない。

今後のエフェクトでは、次のように一体のHelperが複数の責務を同時に持つ。

- 重力球本体とRoot周囲の巡回回転移動
- 汎用明光弾と巡回回転移動と攻撃判定
- 三角光弾などの別素材と同じ巡回回転移動

一方、フィボナッチ・ライトのように巡回回転移動を必要としないエフェクトもある。エフェクト種別ごとに実行経路を固定するのではなく、Helperが持つ責務を合成できる共通実行基盤が必要である。

Helperの通常変数とシステム変数はHelper個体ごとに独立するため、兄弟Helper同士で同じ変数番号を使用しても値は競合しない。一体のHelperへ複数責務を合成する場合だけ、責務間の変数割当てが問題となる。

## 決定

### 適用範囲

一定の用途と有限寿命を持って生成される非常駐Helperは、責務ビットによる共通ルーティングを使用する。共通エフェクのHelperに加え、技や攻撃の有限寿命Helperも対象とする。

Root、常駐Helper、ExplodおよびProjectileは対象外とする。常駐Helperは従来どおりStateDef `-2`、共通IDルーティングおよびStateDef `5150`を使用する。

既存の非常駐Helperは、表示、座標、速度、周期、生成数および寿命を変えない構造移行として段階的に共通ルーティングへ移す。

### 個別初期化と初期化完了

非常駐Helperは、その用途に対応する個別初期化StateDefから開始する。個別初期化StateDefは次の処理を行う。

1. 必要な責務ビットを設定する。
2. 共通ヘッダーと各責務の調整値を初期化する。
3. Helper私有経過tickを`0`にする。
4. すべての値を保存した後に初期化完了ビットを設定する。
5. 同じtickに共通起点StateDefへ移動する。

共通起点StateDefはエフェクト固有の初期値を推測または再設定しない。初期化完了ビットがないHelperを責務処理へ送らない。

### 責務ビットと固定順ルーティング

Helper自身のシステム整数変数`sysvar`へ、そのHelperが実行する責務のビットマップを保持する。複数の責務ビットは同時に設定できる。責務ビットのマスク値は共通変数文書を正本とし、エフェクトごとに独自定義しない。

すべての対象Helperは、毎tick一回、共通起点StateDefから固定された責務ルーター列へ入る。各責務ルーターは対応ビットの有無を読み、ビットがある場合は対応する個別責務StateDefを一つ実行し、ビットがない場合はそのまま次の責務ルーターへ進む。個別責務StateDefの完了後も、共通起点に戻らず、次の責務ルーターへ進む。

責務の実行順は固定する。基礎となるエフェク本体の処理後に座標運動を適用し、完成座標が必要な攻撃判定と描画完成処理をその後に行う。重力球責務と巡回回転移動責務が同時に有効な場合は、重力球責務、巡回回転移動責務の順に実行する。

現在のStateDefが当該tickのルーティング進行位置を表すため、実行済み責務ビットや可変のルートカーソルは保持しない。

### 終端StateDefと次tickへの復帰

最後の責務ルーターは、完了後に共通終端StateDefへ移動する。共通終端StateDefは同一tick中に共通起点へ戻らず、`time>=1`となる次tickに共通起点StateDefへ戻る。

`time`はこの同一tick再進入を防ぐ一tickの障壁にだけ使用する。表示、移動、攻撃、周期生成、経過段階、寿命および終了判定にStateDefの`time`を使用しない。

非常駐Helperは共通StateDef `5150`を経由しない。寿命または終了条件へ到達した場合は、後始末を行った後に`DestroySelf`を実行する。

### Helper私有経過tick

非常駐Helperは、StateDefを移動してもリセットされないHelper私有経過tickを保持する。生成tickの最初の責務周期では`0`とし、固定順の全責務を実行した後に一度だけ加算する。終端StateDefに入った最初の評価で加算し、次tickは共通起点への状態変更を先に実行することで、一処理周期に一度の更新とする。

出現、維持、消滅、周期生成、回転角および寿命は、このHelper私有経過tickを時間基準とする。例えば、周期生成は私有経過tickと生成周期の剰余から求め、巡回回転角は初期位相と私有経過tickと角速度から求める。

Rootの`private-gametime`は、複数Helper間の同期、共通位相および擬似乱数入力など、キャラクター全体の絶対的な時刻が必要な用途に使用する。Helper生成後の経過を表す私有経過tickの代用にはしない。

本決定は、[ADR 002: private-gametimeの導入](002-private-gametime.md)の「StateDef経過時間には`time`を使用する」という決定に対する、共通責務ルーティング対象の非常駐Helperに限定した後発の例外とする。

### 共通変数ABI

すべての対象Helperは、次の三層からなる変数ABIに従う。

1. 共通ヘッダー：責務ビット、初期化完了、終了状態、Helper私有経過tickおよび共通寿命。
2. 責務別領域：巡回回転移動、攻撃判定、重力球など、共通責務StateDefが読み書きする値。
3. 用途固有領域：個別素材、色、局所的な表示設定など、当該用途のStateDefだけが使用する値。

共通ルーターは共通ヘッダーだけを読み書きする。個別責務StateDefはその責務別領域と、必要な共通ヘッダーだけを読み書きする。

同時に有効にできる責務間では、`var`および`fvar`の割当てを重ねない。相互排他が固定された責務または用途のみ、明示的な重ね合わせ契約によって同じ変数領域を利用できる。変数番号を決める前に、既存非常駐Helperの全使用領域と責務間の同時成立関係を監査する。

整数値は、上限、符号、初期化時期、保持期間および部分更新方法を定義できる場合に、ビットフィールドへ集約できる。連続値、上限が未定の値、または保持期間が異なる値を、変数数の削減だけを目的として集約しない。

### `sysvar`使用の例外

WinMUGENの`sysvar(0)`〜`sysvar(4)`は通常、`common1.cns`の内部管理用とされる。本プロジェクトでは、共通責務ルーティング対象の非常駐Helperに限り、そのHelper自身の`sysvar`を共通ヘッダーに使用できるものとする。

この例外はRootと常駐Helperへ適用しない。対象の非常駐Helperは`common1.cns`のStateDefを終了経路または待機経路として使用せず、必要な後始末の後に`DestroySelf`で終了する。

`sysvar`には必要最小限の共通ヘッダーだけを配置する。責務固有値や用途固有値は通常の`var`および`fvar`へ置き、`sysvar`を二重用途で使用しない。具体的な`sysvar`番号、ビット割当て、更新時期および値域は、既存変数の監査後に共通変数文書で固定する。

### StateDef領域

個別エフェクおよび技の初期化StateDefは、従来どおり各用途の予約範囲に置く。

全対象Helperが共有する起点、責務ルーター、共通時間更新、寿命判定および終端は、個別エフェクの1000番予約範囲と分離した、非常駐Helper共通基盤用の予約範囲に配置する。責務の個別実行StateDefを共通基盤範囲または責務を所有する個別範囲のどちらへ配置するかは、StateDef番号と責務の割当てを設計する際に固定する。

この共通基盤範囲は共通エフェク自体ではなく、個別エフェクの予約範囲を横断する明示的な共有基盤とする。

## 結果

非常駐Helperは、表示と寿命を継続したまま複数の個別StateDefを固定順に通過できる。エフェク本体、巡回回転移動、攻撃判定などを一体のHelperへ合成できる。巡回回転移動を必要としないエフェクは、対応責務ビットを設定せずに同じ基盤を使用できる。

StateDefの`time`は終端の一tick障壁だけに限定されるため、責務StateDefを追加または移動しても、出現、発光、拡縮、回転、周期生成および寿命の進行はリセットされない。

一方、共通ヘッダーと責務別領域は全対象Helperが従う固定ABIとなる。新しい責務の追加時は、責務の実行順、同時成立関係、変数領域、初期化時期、保持期間および部分更新契約を追加し、既存の合成可能な責務を壊さないことが必要になる。
