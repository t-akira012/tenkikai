# ADR 006: the_controllerの挙動ルーティング

## 状態

採用

## 背景

`the_controller`はオーラバウンド以外の挙動も管理する。各挙動の判定と処理を一つのStateDefへ集約すると、監視条件と個別処理が混在し、追加時の影響範囲が大きくなる。

## 決定

常駐Helperの共通IDルーティング後、`the_controller`内の挙動を次の階層で分離する。

```text
個別ID集約
→ 挙動集約
→ 挙動個別
```

バウンドでは、`bound集約 → bound個別`の順に遷移する。別の挙動を追加する場合も、`別挙動集約 → 別挙動個別`の階層を追加する。

挙動集約と挙動個別の組を挙動塊とする。すべての挙動塊は固定された順序で毎tick処理する。挙動集約StateDefは、その挙動塊で条件に該当する挙動がある場合に対応する挙動個別StateDefへ遷移し、該当する挙動がない場合は次の挙動集約StateDefへ遷移する。一つの挙動塊に複数の挙動個別StateDefがある場合、そのtickに実行するのは条件に該当する一つ、または0個とする。

挙動個別StateDefの処理完了後は、次の挙動塊がある場合は次の挙動集約StateDefへ遷移する。各挙動塊は固定された順序で連続する。最後の挙動塊だけが最終処理StateDefへ遷移し、最終処理完了後に`SelfState value=5150`を実行する。

個別挙動の途中で`5150`へ移動してはならない。次フレームは`StateDef -2`から共通IDルーティングを経由して監視へ復帰する。監視StateDefへ直接戻すと、発動条件が残ったまま再び個別挙動用StateDefへ遷移し、同じ遷移を繰り返す無限ループになって必ず起動時にクラッシュする。

## 結果

挙動の追加は対応する集約StateDefと個別StateDefの増設で行える。新しい挙動塊を追加した場合は、直前の挙動塊の終了先と、個別挙動なしの場合の遷移先を新しい集約StateDefへ接続する。共通ルーティング、挙動判定、個別処理の責務が分離され、Root側の技StateDefへ演出制御を追加せずに拡張できる。

具体的なStateDef番号と現在の遷移は[the_controller Helper](../state/helper-99004-the-controller.md)に記載する。
