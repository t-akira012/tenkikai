# ADR 029: the_controllerによる本体自由傾斜管理

## 状態

採用

## 背景

前方ダッシュと後方ダッシュは、個別の1tickリースと固定角度、固定Head位置補正を使用していた。この構成では別の技が本体傾斜を利用するたびに、前後別の要求bit、持続変数、Head位置パターンを追加する必要がある。

また、Rootから常駐Helperの変数を直接設定する経路はなく、Rootへ傾斜要求変数を設けると、Body・Head・Auraの変換を`the_controller`へ集約する既存契約に反する。

## 決定

### 管理責務

本体自由傾斜の要求検出、残存時間、目標角度、角速度、現在角度、Body系完成値およびHead完成位置は、すべて`the_controller`が管理する。

RootのStateDefは傾斜変数を設定しない。`the_controller`はRootのStateDefと必要な状態情報を監視し、該当する技または行動の傾斜要求を自身の変数へ登録する。新しい技から自由傾斜を使用する場合も、要求条件と設定値を`the_controller`の要求登録処理へ追加する。

RootはStateDef `-2`で前tickのController完成値をAngleDrawへ適用する。Rootから先に処理されるWinMUGENの実行順により、Controllerが更新した角度のRootへの反映は1tick後となる。この遅延を許容し、Root側へ補償処理または傾斜状態を追加しない。

### 変数

`the_controller`の`var(7)`を自由傾斜状態ビットフィールドとする。

| bit | 用途 |
| ---: | --- |
| 0〜8 | 残存有効tick、0〜511 |
| 9〜15 | 角速度コード、0〜127 |
| 16〜31 | 未使用 |

角速度は角速度コードへ`0.5`を乗じた度/tickとする。コード`0`は角速度なしを表す。残存時間の減算と要求登録では、使用する領域だけを更新し、未使用の上位bitを保持する。

`fvar(19)`を目標角度、既存のBody系完成角度`fvar(7)`を現在角度とする。前方・後方ダッシュ専用だった`var(8)`は本ADRで未使用へ戻し、後に[ADR 030](030-controller-managed-root-screenbound.md)でRoot画面外移動許可booleanへ再割当する。

AngleDraw要求ビットフィールド`var(2)`のbit 2を本体自由傾斜へ割り当て、bit 3を未使用へ戻す。自由傾斜の残存時間がある場合、または現在角度が0ではなく中立復帰中の場合にbit 2を有効にする。

### 角度更新

要求が有効な間は、現在角度を指定角速度で目標角度へ近づけ、目標を越えないように完成値を制限する。要求が期限切れになった後は、保持している角速度で現在角度を0へ近づける。反対符号の目標へ切り替わった場合も同じ更新を用い、現在角度は0を通過してから反対側へ進む。

### Head位置

Headの通常基準位置はRootから上方61pxである。本体自由傾斜中のHead完成Pos補正は、RootのSprite axisを位置基準として現在角度から次の式で求める。前方傾斜ではHeadと本体の間隔を確保するため、X移動係数を後方傾斜より大きくする。

```text
現在角度<0の場合: X補正=-66*sin(現在角度*pi/180)
現在角度>=0の場合: X補正=-61*sin(現在角度*pi/180)
Y補正=61*(1-cos(現在角度*pi/180))
```

Head自身は傾斜させない。Head AuraはHeadの完成位置を参照する既存契約を維持する。

### 前後ダッシュの移行

前方ダッシュStateDef `110`と後方ダッシュStateDef `111`は、`the_controller`がRootの状態を観測して同じ自由傾斜要求へ異なる目標角度と角速度を登録する。前後専用の持続変数、要求bitおよび固定Head位置補正を使用しない。

## 結果

本体傾斜を利用する技は、Controllerへ要求条件と目標角度、角速度、寿命を登録するだけで、Body、Body Aura、HeadおよびHead Auraへ共通の完成値経路を利用できる。

前後ダッシュの方向変更、要求終了後の中立復帰、Headの角度連動移動が同じ現在角度から成立する。RootとControllerの実行順による1tick遅延は仕様として明示される。
